## Fase 5 — Fitur dan perilaku runtime (M4)

- [x] T5.1 Ganti efek saat runtime tanpa kedipan atau restart kamera (FR-05). Selesai: transisi antar efek mulus di kedua platform.
  - Hasil: Transisi runtime antar efek (Blur, Solid Color, Image fit cover/contain, dan NoEffect/bypass) berjalan mulus tanpa menghentikan atau membuat ulang track kamera (FR-05). Di Android dan iOS: `FrameCompositor` dilengkapi method `clearMask()` thread-safe yang secara idempoten mereset status mask saat `clearEffect()` dipanggil, mencegah ghosting/flicker siluet lama saat beralih dari `NoEffect` kembali ke efek aktif. Transisi antar efek aktif (Blur <-> Color <-> Image) mempertahankan mask yang ada sehingga pergantian instan tanpa jeda ke frame mentah. Di Android, penjadwalan segmentasi dipicu langsung pada frame pertama (`!compositor.hasMask || n % 5 == 0`) menghilangkan latensi awal. Ditambahkan unit test transisi efek runtime di kedua platform (`FrameProcessorTest.kt` & `RunnerTests.swift`), seluruh 53 unit test Dart 100% lulus, 37 test JVM lulus, `flutter analyze` 0 issue, serta build iOS dan Android example berhasil 100%.
- [x] T5.2 Parameter kualitas: resolusi segmentasi, edge smoothing, target fps (FR-11). Selesai: perubahan parameter berpengaruh terukur pada fps dan kualitas.
  - Hasil: `BackgroundQuality` (`segmentationWidth`, `edgeSmoothing`, `targetFps`) terekspos di API publik Dart (`lib/src/quality/quality.dart`), lengkap dengan preset bawaan (`low`: 192px/0.25/15fps, `balanced`: 256px/0.5/30fps, `high`: 384px/0.75/30fps), validasi rentang parameter, method `attach(..., quality:)`, dan method runtime `setQuality(quality)`. Di Android (`GpuCompositor.kt` & `FrameProcessor.kt`): resolusi segmentasi mengatur ukuran downsampling readback FBO RGBA secara decoupling tanpa realokasi FBO output kamera; `edgeSmoothing` diintegrasikan langsung ke fragment shader GPU (Blur, Color, Image) menggunakan `smoothstep` dinamis berbasis feather width; dan `targetFps` melakukan rate-limiting terukur dengan mendaur ulang frame terkomposit terakhir (`reuseLastFrame`) saat interval waktu antarframe belum terpenuhi. Interval throttling segmentasi beralih dari hardcode menjadi adaptif dinamis berdasarkan durasi inferensi MediaPipe (1–10 frame, ~3–30 Hz). Monitor FPS native menggunakan sliding window (45 frame / ~1.5 dtk):
    1. **Stage 1 (FPS < 14)**: Resolusi segmentasi otomatis diturunkan dari 256px ke 192px dan interval segmentasi dinaikkan, memancarkan event `PerformanceFallbackEvent` dengan `action: qualityDegraded`.
    2. **Stage 2 (FPS < 10 pada 2 window berturut-turut)**: Efek dinonaktifkan secara otomatis (`clearEffect()`), status beralih ke `idle`, frame kembali ke bypass nol-alokasi, dan memancarkan event `PerformanceFallbackEvent` dengan `action: disabled` tanpa crash atau freeze.
