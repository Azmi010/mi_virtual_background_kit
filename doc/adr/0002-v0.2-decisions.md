# ADR 0002 — Keputusan v0.2

Status: Draft — bagian 1–4 (T12.4) dan 9 (T12.5) selesai; bagian 5–8 menunggu spike T13.1–T13.4
Tanggal: 10 November 2026
Milestone: M7 — prasyarat dan spike v0.2
Referensi: [PRD-v0.2-v0.3.md](../dev/PRD-v0.2-v0.3.md), [TASKS-v0.2-v0.3.md](../dev/TASKS-v0.2-v0.3.md)

## Konteks

v0.2 menambah package kedua: adapter LiveKit. Satu repo harus melayani dua package
yang dirilis terpisah ke pub.dev. Posisi awal saat ini:

- Satu package di root; publish otomatis lewat tag `v*` (T10.3, sudah jalan — tag
  `v0.1.0` dan `v0.1.1` terbit).
- PRD-v0.2-v0.3 bagian 9 mengizinkan dua opsi mekanisme pengembangan: pub workspace
  atau path dependency dengan dependensi versi terbit saat rilis.

## Keputusan

### 1. Struktur repo: satu repo, core di root, adapter di `livekit/`

Sesuai PRD-v0.2-v0.3 bagian 11. Tidak ada repo terpisah, tidak ada federated plugin.

```
mi_virtual_background_kit/          # package core (publish dari root)
  pubspec.yaml                      # + field workspace (bagian 2)
  livekit/                          # package mi_virtual_background_kit_livekit
    pubspec.yaml
  example/                          # di luar workspace, resolusi sendiri
```

### 2. Pengembangan: pub workspace (bukan path dependency)

- Root `pubspec.yaml` (core) menambah `workspace: [livekit]`.
- `livekit/pubspec.yaml` menambah `resolution: workspace` dan dependensi core
  **hosted**: `mi_virtual_background_kit: ^0.2.0`. Di dalam workspace, pub memakai
  versi lokal; di luar (konsumen), pub memakai versi hosted. Tidak ada langkah
  "ganti path ke hosted" sebelum publish.
- `sdk` core naik `^3.5.0` → `^3.6.0` dan `flutter` `>=3.24.0` → `>=3.27.0`
  (syarat minimum workspace: semua paket workspace `^3.6.0`). Dicatat di CHANGELOG
  0.2.0 bagian Breaking/Notes.
- `.pubignore` root menambah baris `livekit/` agar folder adapter tidak ikut
  terkirim ke arsip pub.dev milik core.
- `example/` tidak ikut workspace: punya alur `pub get` dan symlink build sendiri
  (`tool/link_example_build.sh`), tidak perlu berubah.

Verifikasi (10 Nov 2026, scratch package + `dart pub publish --dry-run`):

- Workspace root yang publishable lolos validasi publish.
- Folder workspace yang di-`.pubignore` tidak masuk arsip dan validasi tetap lolos.
- Field `workspace` pada paket yang dijadikan dependensi diabaikan aman oleh
  resolver konsumen (mengarah ke path yang tidak ada pun tidak error).
- Dependensi antar-paket workspace dengan constraint hosted resolve ke versi lokal.

Alternatif ditolak — path dependency + swap manual ke hosted sebelum publish:
pub.dev menolak path dependency saat publish, jadi langkah swap wajib dan bisa
lupa; workspace menghapus langkah itu tanpa biaya tambahan.

Konsekuensi yang diterima: min SDK konsumen naik ke Dart 3.6 / Flutter 3.27.

### 3. Skema tag: per package, dua pola

| Package | Tag | Pola di pub.dev |
|---|---|---|
| core | `v0.2.0` (tidak berubah) | `v{{version}}` |
| adapter | `livekit-v0.2.0` | `livekit-v{{version}}` |

Core mempertahankan pola `v*`: sudah terkonfigurasi dan terbukti di T10.3, riwayat
tag `v0.1.0`/`v0.1.1` tetap valid, tidak perlu membuka ulang setup pub.dev.
Adapter memakai prefiks nama package — pola yang disarankan dokumentasi dart-lang
untuk repo multi-package.

Alternatif ditolak — prefix semua paket (`core-v*` + `livekit-v*`): simetris, tetapi
wajib mengubah konfigurasi tag pub.dev untuk core yang sudah jalan, tanpa keuntungan
fungsional.

### 4. Workflow publish (revisi rencana — implementasi di Fase 15)

`.github/workflows/publish.yml` (core) **tidak berubah**. Ditambah satu file baru
saat scaffold adapter (T15.1):

```yaml
# .github/workflows/publish_livekit.yml
name: Publish LiveKit adapter to pub.dev

on:
  push:
    tags:
      # must match the tag-pattern configured on pub.dev: 'livekit-v{{version}}'
      - 'livekit-v[0-9]+.[0-9]+.[0-9]+'

jobs:
  publish:
    permissions:
      id-token: write # Required for authentication using OIDC
    uses: dart-lang/setup-dart/.github/workflows/publish.yml@v1
    with:
      working-directory: livekit
```

Urutan rilis: **core dulu** (tag `v0.2.0` → tunggu tampil di pub.dev), baru adapter
(tag `livekit-v0.2.0`). Urutan ini dipaksa oleh pub: validasi publish adapter
membutuhkan `mi_virtual_background_kit ^0.2.0` sudah tersedia hosted.

CI (`ci.yml`) tidak diubah di T12.4; penyesuaian workspace dan job analyze/test
adapter masuk bersama T15.1 dan matriks versi T17.4.

## Keputusan yang belum diambil (menunggu spike)

- **5. Mekanisme adapter LiveKit** — menunggu T13.1 (ditulis di T13.5).
- **6. Penanganan track shared** — menunggu T13.2.
- **7. Desain temporal smoothing mask** — menunggu T13.3.
- **8. Strategi perangkat lambat/32-bit** — menunggu T13.4.
- **9. Kebijakan perubahan API pada 0.x** (T12.5, ditetapkan 10 Nov 2026):
  1. **Penambahan subclass `sealed class VirtualBackgroundEffect`** (mis. `VideoEffect`
     di v0.3) dan **kode error baru pada hierarki `BackgroundException`** (mis.
     `invalidVideo`) boleh masuk di versi **minor**, bukan patch — konsumen dengan
     `switch` eksaustif akan rusak. Wajib: entri CHANGELOG berlabel **Breaking:**,
     catatan di README/FAQ bila perilakunya menyesatkan, dan konfirmasi lewat centang
     "Public API change" di template PR.
  2. **Field baru `BackgroundQuality`** (mis. `maskTemporalSmoothing`, `autoRecovery`)
     bukan breaking **selama** punya nilai bawaan yang mempertahankan perilaku versi
     sebelumnya. Field tanpa nilai bawaan diperlakukan seperti butir 1.
  3. Perubahan lain yang menghapus atau mengubah signature API publik mengikuti
     butir 1: minor + label Breaking.
  4. Label **Breaking** hanya untuk perubahan yang memaksa konsumen mengubah kode;
     penambahan API yang murni aditif tidak diberi label.
