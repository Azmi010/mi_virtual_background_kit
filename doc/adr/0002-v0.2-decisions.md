# ADR 0002 — Keputusan v0.2

Status: Final — bagian 1–4 (T12.4) dan 9 (T12.5); bagian 5–8 ditutup di T13.5 dari spike T13.1–T13.4
Tanggal: 10–11 November 2026
Milestone: M7 — prasyarat dan spike v0.2
Referensi: [PRD-v0.2-v0.3.md](../dev/PRD-v0.2-v0.3.md), [TASKS-v0.2-v0.3.md](../dev/TASKS-v0.2-v0.3.md),
angka spike di [../spike-results.md](../spike-results.md) bagian T13.1–T13.4

## Konteks

v0.2 menambah package kedua: adapter LiveKit. Satu repo harus melayani dua package
yang dirilis terpisah ke pub.dev. Posisi awal saat ini:

- Satu package di root; publish otomatis lewat tag `v*` (T10.3, sudah jalan — tag
  `v0.1.0` dan `v0.1.1` terbit).
- PRD-v0.2-v0.3 bagian 9 mengizinkan dua opsi mekanisme pengembangan: pub workspace
  atau path dependency dengan dependensi versi terbit saat rilis.
- Bagian 5–8 bergantung pada spike T13.1 (mekanisme LiveKit), T13.2 (track shared),
  T13.3 (smoothing), dan T13.4 (perangkat lambat) — semuanya selesai 11 November 2026.

## Keputusan

### 1. Struktur repo: satu repo, core di root, adapter di `livekit/`

Sesuai PRD-v0.2-v0.3 bagian 11. Tidak ada repo terpisah, tidak ada federated plugin.

```
mi_virtual_background_kit/          # package core (publish dari root)
  pubspec.yaml                      # + field workspace (bagian 2)
  livekit/                          # package mi_virtual_background_kit_livekit
    pubspec.yaml
  example/                          # di luar workspace, resolusi sendiri
```

### 2. Pengembangan: pub workspace (bukan path dependency)

- Root `pubspec.yaml` (core) menambah `workspace: [livekit]`.
- `livekit/pubspec.yaml` menambah `resolution: workspace` dan dependensi core
  **hosted**: `mi_virtual_background_kit: ^0.2.0`. Di dalam workspace, pub memakai
  versi lokal; di luar (konsumen), pub memakai versi hosted. Tidak ada langkah
  "ganti path ke hosted" sebelum publish.
- `sdk` core naik `^3.5.0` → `^3.6.0` dan `flutter` `>=3.24.0` → `>=3.27.0`
  (syarat minimum workspace: semua paket workspace `^3.6.0`). Dicatat di CHANGELOG
  0.2.0 bagian Breaking/Notes.
- `.pubignore` root menambah baris `livekit/` agar folder adapter tidak ikut
  terkirim ke arsip pub.dev milik core.
- `example/` tidak ikut workspace: punya alur `pub get` dan symlink build sendiri
  (`tool/link_example_build.sh`), tidak perlu berubah.

Verifikasi (10 Nov 2026, scratch package + `dart pub publish --dry-run`):

- Workspace root yang publishable lolos validasi publish.
- Folder workspace yang di-`.pubignore` tidak masuk arsip dan validasi tetap lolos.
- Field `workspace` pada paket yang dijadikan dependensi diabaikan aman oleh
  resolver konsumen (mengarah ke path yang tidak ada pun tidak error).
- Dependensi antar-paket workspace dengan constraint hosted resolve ke versi lokal.

Alternatif ditolak — path dependency + swap manual ke hosted sebelum publish:
pub.dev menolak path dependency saat publish, jadi langkah swap wajib dan bisa
lupa; workspace menghapus langkah itu tanpa biaya tambahan.

Konsekuensi yang diterima: min SDK konsumen naik ke Dart 3.6 / Flutter 3.27.

### 3. Skema tag: per package, dua pola

| Package | Tag | Pola di pub.dev |
|---|---|---|
| core | `v0.2.0` (tidak berubah) | `v{{version}}` |
| adapter | `livekit-v0.2.0` | `livekit-v{{version}}` |

Core mempertahankan pola `v*`: sudah terkonfigurasi dan terbukti di T10.3, riwayat
tag `v0.1.0`/`v0.1.1` tetap valid, tidak perlu membuka ulang setup pub.dev.
Adapter memakai prefiks nama package — pola yang disarankan dokumentasi dart-lang
untuk repo multi-package.

Alternatif ditolak — prefix semua paket (`core-v*` + `livekit-v*`): simetris, tetapi
wajib mengubah konfigurasi tag pub.dev untuk core yang sudah jalan, tanpa keuntungan
fungsional.

### 4. Workflow publish (revisi rencana — implementasi di Fase 15)

`.github/workflows/publish.yml` (core) **tidak berubah**. Ditambah satu file baru
saat scaffold adapter (T15.1):

```yaml
# .github/workflows/publish_livekit.yml
name: Publish LiveKit adapter to pub.dev

on:
  push:
    tags:
      # must match the tag-pattern configured on pub.dev: 'livekit-v{{version}}'
      - 'livekit-v[0-9]+.[0-9]+.[0-9]+'

jobs:
  publish:
    permissions:
      id-token: write # Required for authentication using OIDC
    uses: dart-lang/setup-dart/.github/workflows/publish.yml@v1
    with:
      working-directory: livekit
```

Urutan rilis: **core dulu** (tag `v0.2.0` → tunggu tampil di pub.dev), baru adapter
(tag `livekit-v0.2.0`). Urutan ini dipaksa oleh pub: validasi publish adapter
membutuhkan `mi_virtual_background_kit ^0.2.0` sudah tersedia hosted.

CI (`ci.yml`) tidak diubah di T12.4; penyesuaian workspace dan job analyze/test
adapter masuk bersama T15.1 dan matriks versi T17.4.

### 5. Mekanisme adapter LiveKit: re-attach berbasis event (T13.1)

Ditetapkan 10 November 2026 dari spike 4 mekanisme × 7 stage di A1
(`livekit_client 2.13.1`; angka di spike-results bagian T13.1).

**Keputusan: mekanisme C** — adapter memanggil API inti `attach(mediaStreamTrack)`
sekali, lalu memasang ulang efek saat track direstart lewat event
`TrackStreamUpdatedEvent` dengan pencocokan nama track. Adapter tetap tipis;
seluruh logika efek tetap di core (FR-14, FR-16).

Bukti: mekanisme A (attach sekali) dan B (`setProcessor`) kehilangan efek di S2
(ganti kamera) dan tidak pulih — `restartTrack` memanggil `stop()` yang melepas
processor. C dan D mempertahankan efek di semua stage (teal ≥ 30%).

Alternatif ditolak:

- **B/D (hook `setProcessor` milik LiveKit)** — efek tetap hilang saat restart
  karena alasan yang sama, dan bergantung titik pemasangan internal LiveKit yang
  lebih rentan berubah antarversi.
- **D dibanding C** — D hanya memindahkan ketergantungan ke hook internal tanpa
  keuntungan; C cukup karena pemulihan hanya membutuhkan event.

Risiko dan mitigasi: pemulihan bergantung `TrackStreamUpdatedEvent` (event
internal) → pencocokan nama track, plus CI matriks `livekit_client` batas
bawah/atas (T15.4) dengan rentang versi eksplisit (T15.1). Spike menguji 2.13.1.

### 6. Penanganan track shared: didukung penuh lewat redirect di jalur attach (T13.2)

Ditetapkan 11 November 2026 (angka di spike-results bagian T13.2).

**Keputusan: FR-19 opsi (b)** — `attach` memilih objek yang benar-benar
memproses frame; track shared didukung penuh di kedua platform tanpa fork
`flutter_webrtc`:

- **Android**: identitas wrapper registry dibandingkan dengan
  `VideoSource.videoProcessor` (dua field privat + `getCapturerInfo`,
  `SharedTrackProbe`). Sama → pasang langsung; berbeda (shared, registry
  replacement, normal) → pasang di objek milik source. Reflection gagal →
  degradasi ke perilaku lama dengan log `reason=reflection-failed`, tidak
  pernah crash.
- **iOS**: deteksi `track.processing` (KVC); nil → redirect ke
  `videoCapturer?.delegate`, lalu fallback `retainedAdapter`. Kit menyimpan
  adapter lintas detach karena wrapper asli adalah pemilik kuat tunggal
  adapter (delegate lemah) — tanpa ini `getMediaTracks()` + detach mematikan
  rantai kamera.

Bukti: teal ≥ 33% semua stage di A1; ≥ 37% S1/S3–S5 di iPhone 15 (S2 iOS 0% =
`getUserMedia` kedua berantai mandiri — perilaku benar; efek menempel setelah
attach biasa).

Alternatif ditolak: **deteksi + error `sharedTrack` yang jelas** (FR-19 opsi a)
— batas yang direncanakan, ternyata dukungan penuh mungkin tanpa fork; tetap
dipertahankan sebagai jalur degradasi bila reflection/KVC berubah.

Produksi: jalur ini dipindahkan ke lokasi permanen dan diuji di T14.1 (unit test
reflection gagal / `processing` nil, regression test jalur encoder `toI420()`).
Risiko: bergantung field privat `flutter_webrtc` → dipegang rentang versi
`^1.6.2` dan degradasi aman, sesuai prinsip tanpa fork ADR 0001.

### 7. Desain temporal smoothing mask: EMA adaptif di jalur CPU (T13.3)

Ditetapkan 11 November 2026 (angka di spike-results bagian T13.3).

**Keputusan:**

- Mode **`adaptive`** dengan bawaan **`maskTemporalSmoothing = 0.7`** dan
  `D0 = 0.06`: `out = prev * s + raw * (1 - s)` seperti EMA biasa, tetapi
  bobot riwayat diturunkan menuju 0 saat inovasi mask `d` melewati `D0` —
  gerak cepat menarik mask segar (tanpa ghosting), keadaan diam tetap mulus.
- Nilai **0 = identik v0.1** (syarat FR-20 kompatibilitas mundur; terverifikasi
  mode `none` = baseline persis).
- Angka pemilihan: kedipan saat diam **−71% (A1) / −72% (iOS)**; ghosting
  `lag` ≤ 0,5% di semua stage; fps tanpa regresi (iOS terkunci 30,0).
- **Penempatan: CPU, saat upload mask**, di kedua platform — bukan GPU blend
  seperti draf PRD bagian 9. Biaya blend tidak terukur dalam noise spike
  (didominasi instrumentasi metrik dan build debug), mask kecil (49.152 px di
  Android), dan menambah pass GL/Core Image adalah optimasi prematur. Buka
  kembali keputusan ini hanya jika profil produksi (release, tanpa metrik)
  menunjukkan bottleneck di situ.
- Riwayat di-reset saat ganti stage/efek/clear.

Field baru `BackgroundQuality.maskTemporalSmoothing` (0..1, bawaan 0.7):
non-breaking menurut bagian 9. Angka 0.4 pada contoh draf PRD bagian 8.3
diganti mengikuti keputusan ini.

Alternatif ditolak: **EMA tetap non-adaptive** — ghosting naik seiring s
(ema 0.7 → lag 3,3–6,4%, terlihat mata); **tanpa smoothing (v0.1)** — kedipan
baseline; **`D0` besar** — mengejar target −50% kedipan saat motion tetapi
membuka ghosting.

Risiko: target PRD −50% kedipan saat motion baru tercapai −27..30% dengan
`D0 = 0.06` (terlalu konservatif untuk gerak) → hutang tuning T14.2: naikkan
`D0` ke ~0.10–0.12 lalu ukur ulang pada klip uji tetap. Catatan pelaksanaan:
mask iOS berukuran penuh 640×480 (`segmentationWidth` tidak mengecilkan mask di
iOS) — periksa bersama T14.2/T14.3.

**Ditutup T14.2/T14.3 (12 November 2026, angka di `doc/smoothing-raw/`,
sapuan `FlickerTestPage` none/0.06/0.10/0.12 × still/motion):**

- Hutang tuning **ditolak**: `D0` 0.10 dan 0.12 diuji di A1 dan iPhone 15 —
  kedipan motion hanya turun +20..32% di kedua platform (tidak bergerak berarti
  dari `D0 = 0.06`) sementara `lag` naik 0,46% → 1,09–1,20% (melampaui batas
  0,5%). **`D0` default tetap 0,06 dan `s` tetap 0,7 — nol perubahan kode.**
- Target −50% PRD §7: **tercapai saat diam** (A1 +50/+71/+79%; iPhone re-run
  bersih +68/+59/+75%) dan **tidak tercapai saat gerak** di rentang D0 yang
  diuji — dicatat sebagai batasan, bukan kegagalan implementasi.
- Paritas platform terkonfirmasi pada still dan pola motion; angka motion
  iPhone bervariasi antar run (−59%..+33%, script gerak operator) — klaim
  lintas platform memakai run yang sama per platform.
- Run iPhone pertama gagal valid untuk still (subjek bergerak: `d` 5–7×
  baseline) — bukti protokol klip harus ketat; run kedua valid.
- fps tanpa regresi (A1 ~25, iPhone terkunci 30,0); `us/mask` tetap didominasi
  instrumentasi metrik sesuai temuan T13.3.

### 8. Strategi perangkat lambat/32-bit (T13.4)

Ditetapkan 11 November 2026, seluruhnya di A1 (angka di spike-results bagian
T13.4; bench terisolasi dari pipeline live, semua angka build debug — angka
absolut rilis lebih rendah, perbandingan relatif valid):

| Kandidat | Angka | Keputusan |
|---|---|---|
| Model `selfie_segmenter_landscape` (144×256) | med 87,9 ms vs 133,1 (−34%), agree 98,9% / IoU 96,8%, ukuran sama 250 KB | **Dipilih** — pengganti square sebagai default, implementasi T14.2/T14.5 |
| Strategi `always` (segmentasi tiap worker idle) | gap 158 ms vs 318 ms (mask 2× lebih segar), fps identik 24,9–25,0 | **Kandidat default**; dikunci setelah T17.1 (baterai/thermal; duty cycle 82% vs 40%) — kalau hasil T17.1 buruk, kembali ke `current` |
| Strategi `current` (mapping v0.1) | gap 318 ms, fps 25,0 | Berlaku sebagai baseline sampai T17.1; FR-12 tetap perlindungan akhir |
| Strategi `budget` | gap 405 ms (paling basi) | **Ditolak** |
| Delegate GPU MediaPipe | SIGABRT `image_frame.cc:102` format UNKNOWN, 3 run termasuk setelah detach | **Ditolak** — gagal konversi hasil GPU → `abort()` native tak tertangkap, independen dari segmenter lain |
| Model `selfie_multiclass_256x256` | med 2.430 ms (18×), init 835 ms, 16,4 MB; kualitas 99,7% | **Ditolak** — binary sudah cukup (99,7% agreement), latensi dan ukuran tak wajar |
| Readback width 144 | −9% saja | **Ditolak** sebagai lever utama; combo landscape + 144 diuji di T14.5 |

Kutipan penolakan GPU:
`Abort message: 'image_frame.cc:102] Check failed: ImageFormat::UNKNOWN != format_ (0 vs. 0)`
— stack `TaskRunner → ImageSegmenter.convertToTaskResult →
PacketGetter.nativeGetImageWidth`.

Risiko: `always` berdampak pada baterai dan thermal yang belum terukur →
syarat penguncian di T17.1; sampai itu `current` tetap default produksi.
Model landscape diuji pada buffer kamera landscape (hook selalu menerima buffer
kamera, bukan crop UI) — sumber potret tidak diuji, risiko rendah.

### 9. Kebijakan perubahan API pada 0.x (T12.5, ditetapkan 10 November 2026)

  1. **Penambahan subclass `sealed class VirtualBackgroundEffect`** (mis. `VideoEffect`
     di v0.3) dan **kode error baru pada hierarki `BackgroundException`** (mis.
     `invalidVideo`) boleh masuk di versi **minor**, bukan patch — konsumen dengan
     `switch` eksaustif akan rusak. Wajib: entri CHANGELOG berlabel **Breaking:**,
     catatan di README/FAQ bila perilakunya menyesatkan, dan konfirmasi lewat centang
     "Public API change" di template PR.
  2. **Field baru `BackgroundQuality`** (mis. `maskTemporalSmoothing`, `autoRecovery`)
     bukan breaking **selama** punya nilai bawaan yang mempertahankan perilaku versi
     sebelumnya. Field tanpa nilai bawaan diperlakukan seperti butir 1.
  3. Perubahan lain yang menghapus atau mengubah signature API publik mengikuti
     butir 1: minor + label Breaking.
  4. Label **Breaking** hanya untuk perubahan yang memaksa konsumen mengubah kode;
     penambahan API yang murni aditif tidak diberi label.
